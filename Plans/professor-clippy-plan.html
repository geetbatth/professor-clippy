Professor Clippy 📎

A paperclip professor clipped to an always-on-top sticky note. Any agent on this PC can leave you notes, reminders and questions through MCP. Every message is mirrored to WhatsApp, and you can chat with Clippy (headless Claude Code) from the desk or your phone.

Architecture

Phase 1 · Foundation

Scaffold — workspace, Electron shell, shared types

  1. pnpm workspace. Set up packages/shared, apps/desktop, apps/mcp, apps/hook and apps/worker, with strict TS, ESLint, Vitest and a root pnpm dev.
  2. Electron shell. electron-vite with React in the renderer. A single-instance lock so a second launch focuses the existing Clippy.
  3. Shared message model. zod schemas for Message, Reminder, Ask and Reply, used by the app, MCP server, hook and Worker alike.
  4. App data dir. %APPDATA%/professor-clippy/ holds clippy.db, token (random, created on first run), port and settings.json.
Phase 2 · Engine

Core service — store, local API, scheduler

This all lives in Electron's main process. The note window, desk chat and WhatsApp all read the same store, so a message dismissed or answered on one side is done everywhere (decision 27).

  1. Store. better-sqlite3 with migrations. Tables are messages, reminders and kv (session id, last WhatsApp inbound time, window position).
  2. Local API. Bound to 127.0.0.1 on a random port, which is written to the port file. Every request needs Authorization: Bearer <token>. Routes: POST /messages, POST /reminders, DELETE /reminders/:id, POST /asks, GET /asks/:id?wait=600 (long-poll), GET /messages.
  3. Scheduler. A single timer armed for the next due_at. The rrule package computes the next fire for recurring reminders. On boot and on resume (powerMonitor), reminders that fired while the PC was off are marked "missed while you were away".
  4. Event bus. Main-process events (message:new, message:done, ask:answered) fan out to the renderer over IPC and to the relay (Phase 6).
  5. Tests. Vitest covering the store, RRULE next-fire, long-poll timeout and token rejection.
Phase 3 · The funny part

Sticky note + Professor Clippy — window, character, antics

Mini mode (idle)
  • ~120×140 transparent window in a corner
  • Just Clippy plus an unread badge
  • Drag anywhere; position is remembered per display
  • Idle life: blinks, adjusts glasses, reads a tiny book, falls asleep (zzz)
Expanded (new message)
  • Yellow sticky note slides out; Clippy clips onto its top edge
  • Note stack (newest on top), a quip speech bubble and a chat box
  • Done / Snooze / Answer buttons per note
  • History tab with search
Attention escalation
  • New message: jump out of mini mode with an eyebrow waggle
  • Ignored for 2 min: taps on the "glass"
  • Ignored for 10 min: bigger antics (urgent messages start here)
  • Each stage plays a sound; mute toggle
  1. Window. BrowserWindow with frameless, transparent, skipTaskbar and setAlwaysOnTop(true, 'screen-saver') so it stays above everything. Mini and expanded are two sizes of the same window. The transparent area is click-through via setIgnoreMouseEvents(true, {forward:true}).
  2. Clippy SVG rig. An original design: a bent-wire paperclip body, googly eyes with pupils that track the cursor, eyebrows, a mortarboard with a swinging tassel, round glasses and a tiny tweed bow tie. Parts are separate SVG groups so CSS keyframes can animate each one.
  3. Animation states. idle, blink, read, sleep, wake, jump, tap-glass, think (while the brain is replying) and celebrate (all notes done). A small state machine in the renderer picks them.
  4. Note stack + history. Unread stack with Done and Snooze (10m / 1h / tomorrow). The History tab uses SQLite FTS search. Ask cards show the question with an answer box.
  5. Quips & unsolicited advice. A JSON pack of canned one-liners, tagged by context (build, error, reminder, late-night). Unsolicited advice fires at random 30–90 min intervals ("It looks like you're writing a for-loop. Would you like me to judge it?"), with an off switch.
  6. Sounds. Original short dings and boings (not Microsoft assets), with a mute toggle in settings and on right-click.
The character must be original and only inspired by Clippy, with no Office sprites or sounds. That keeps you safe if you ever share it.
Phase 4 · Agents in

MCP server + Claude Code wiring

ToolArgsBehaviour
leave_messagebody, urgent?, title?Posts a note. The sender and project are filled in automatically from the cwd and client name.
remind_mebody, when (ISO or natural), repeat? (RRULE)Creates a reminder, synced to the Worker. Returns the id and a human-readable time.
ask_userquestion, options?, timeout_s = 600Long-polls until you answer on the desk, by WhatsApp quote-reply, or through Clippy. On timeout it returns {status:"pending", id}.
check_replyidNon-blocking check on an earlier ask.
list_reminders / cancel_reminder—/idManage reminders.
  1. Server. @modelcontextprotocol/sdk over stdio. It reads port and token from the app data dir. If the app isn't running, it launches it and retries.
  2. Long-running ask. Send MCP progress notifications every 30s while waiting, and set MCP_TOOL_TIMEOUT in the Claude Code env so a 10-minute wait isn't cut off.
  3. Hook script. apps/hook reads the hook JSON from stdin. On Stop it posts "✅ <project> agent finished" with the last assistant line; on Notification it posts "🔐 needs permission" as urgent. It skips the post if the app is down, and can be toggled in settings.
  4. Wiring script. Runs claude mcp add --scope user clippy -- node …/mcp.js, merges the Stop and Notification hooks into ~/.claude/settings.json, and appends the hint line to ~/.claude/CLAUDE.md. It's idempotent, with a matching uninstall.
CLAUDE.md hint: "When the user asks you to leave a message, remind them, notify them, or check with them, use the Professor Clippy MCP tools (leave_message / remind_me / ask_user)."

  1. Spawn the CLI. claude -p <msg> --resume <id> --output-format stream-json --append-system-prompt <persona> --mcp-config clippy.json, running under your Claude Code login with no API key. The session id is stored in kv, and "New chat" clears it.
  2. Permissions (decision 11). --allowedTools: Read, Glob, Grep, WebSearch, WebFetch and the mcp__clippy__* tools. --disallowedTools: Edit, Write, Bash, NotebookEdit. The working dir is set to your home folder.
  3. Persona prompt. A smug, helpful, slightly pompous paperclip professor. Short replies, especially over WhatsApp. It can answer pending agent questions for you with an answer_pending tool.
  4. Streaming UI. Clippy uses the think animation while tokens stream into a speech bubble or the chat pane. WhatsApp gets the final text in one message.
  5. Turn queue. Desk and WhatsApp share one session, so turns are serialised: a message arriving mid-turn waits its turn.
Phase 6 · Phone

WhatsApp via Meta Cloud API + Cloudflare Worker

The Worker is the only thing with a public URL. It holds the Meta token, receives the webhook, decides between free-form and template sends, and fires reminders even when the PC is off. A single Durable Object (SQLite-backed) keeps the queue and reminders, and its alarm fires at each reminder's exact due time. That alarm is how decision 20's "Worker cron" gets implemented.

Inside 24h of your last WA message
  • Free-form text, full length
  • Free
Outside the 24h window
  • Utility template clippy_note: "Professor Clippy 📎: {{1}}"
  • Body cut at ~1000 chars + "…more on desktop"
  • Small Meta fee per message
  1. Meta setup (manual, guided). Create a Meta app with the WhatsApp product, using the test number (decision 14). Add your phone as a verified recipient. Create a system user with a permanent token. Submit the clippy_note utility template for approval.
  2. Worker routes. GET /webhook (verify token handshake). POST /webhook (check X-Hub-Signature-256 with the app secret, then queue). POST /send, PUT/DELETE /reminders/:id and GET /ws. Every PC-facing route needs a shared bearer secret.
  3. Relay client. relay.ts keeps an outbound WebSocket to the Durable Object, reconnecting with backoff. Inbound replies are pushed down it and acked, and anything queued while the PC was off drains on connect.
  4. Mirror everything (decision 15). Every new note, reminder and ask goes to /send. The Worker picks free-form or template from the last-inbound time and returns the wamid, which the app stores in messages.wa_id.
  5. Routing (decision 17). If an inbound message has context.id equal to an ask's wa_id, it answers that ask. Otherwise it goes to the brain as a plain chat turn. Inbound text marks matching notes done when you reply "done" in a quote.
  6. Reminders off-PC. When the alarm fires, the Worker sends the WhatsApp and records sent_at. The desktop only shows the reminder (or "missed while you were away") and doesn't re-send it.
Test number caveats. It only sends to verified recipients (you, fine). The permanent token must come from a system user, not the 24h token on the dashboard. Meta may change test-number limits, and swapping to a real number later only changes the Worker config.
Phase 7 · Ship it

Install + polish

  1. Installer. electron-builder NSIS, per-user, with no admin rights needed. The first-run wizard covers the Worker URL and secret (or "skip WhatsApp for now"), sound, and unsolicited advice on or off.
  2. Auto-start. app.setLoginItemSettings({ openAtLogin: true }), toggleable in settings.
  3. Claude wiring. The first run offers to run the Phase 4 wiring script for the MCP server, hooks and CLAUDE.md hint, showing exactly what it will change.
  4. Worker deploy. pnpm --filter worker deploy via wrangler, with secrets set through wrangler secret put: META_TOKEN, APP_SECRET, VERIFY_TOKEN, PC_SECRET, PHONE_NUMBER_ID, MY_NUMBER.
  5. Settings panel. Toggles for the hook, sounds and unsolicited advice; the ask timeout default; a "New chat" button; and a WhatsApp connection status light.
  6. README. Covers the Meta setup walkthrough, Worker deploy and a troubleshooting section.

Proof

Verification

  1. Unit. Vitest for the store, scheduler RRULEs, API auth, Worker signature check, 24h-window choice and quote-reply routing.
  2. Agent → desk. In a fresh Claude Code session: "leave me a message on Clippy saying hi". Clippy jumps out with the note and the sender shows the project.
  3. Ask round-trip. An agent calls ask_user; quote-reply on WhatsApp; the agent receives the answer. Repeat answering on the desk, then let it time out to get pending.
  4. Reminder while off. Set a reminder 3 min out and close the app or sleep the PC. WhatsApp still arrives, and on restart the desk shows "missed while you were away".
  5. Chat. Ask Clippy something on the desk, then follow up on WhatsApp. Same session, so context carries over. Ask it to edit a file and it refuses.
  6. Install. Reboot: Clippy auto-starts, claude mcp list shows clippy, and the hook fires on agent Stop.
